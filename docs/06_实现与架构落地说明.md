# 实现与架构落地说明

本文档说明代码如何落地前五份文档，以及为可运行演示所做的取舍。生产化改造建议列在末尾。

## 1. 文档到代码的映射

| 文档要求 | 实现 |
|---|---|
| 身份与组织、令牌续期、退出 | `app/auth.py`、`app/routers/auth.py`：JWT 访问令牌 + 随机刷新令牌轮换/撤销，PBKDF2 密码 |
| RBAC 与社区范围 | `get_current_user` / `require_roles` / `community_ids_for`，所有业务查询强制租户与社区条件 |

| 预约与订单冲突、状态机、幂等 | `services/orders.py` + `services/idempotency.py`，API `Idempotency-Key` |

## 2. 关键设计

### 2.1 失败与事务

- 同步请求内完成业务写入，SQLAlchemy Session 作为事务边界。
- 写接口在路由层统一 `commit`；异常向上抛，由全局处理器返回明确 HTTP 状态码与 trace_id。
- 幂等记录与业务写入在同一事务中，避免“业务成功但幂等未落库”。
- 设备事件 `event_no` 由数据库唯一约束兜底；重复投递直接返回首次结果。

### 2.2 权限的三层结构

1. 前端菜单：`/api/auth/me` 返回 `menus`，仅改善体验。
2. 路由依赖：`require_roles` 校验角色；`get_current_user` 校验令牌、用户、租户状态。
3. 领域查询：`scope_statement` 思路与显式 `community_ids` 过滤，居民额外按 `user_id` 限制。

### 2.3 工单关闭门禁

流程：

```text
pending → assigned → accepted → processing → pending_verification → closed
```

- `resolve` 写入维修回填并进入待验收。
- `verify` 同时校验：设备在线、最近心跳 ≤ 60 分钟、测试订单已完成且属于同一设备。
- `close` 再次执行上述校验，防止验收后设备再次离线。
- 这是服务端强约束，不依赖前端按钮状态。

### 2.4 审批状态机

```text
pending → approved → executing → executed
        ↘ rejected
        ↘ failed
```

- 只有财务/管理员可以决策与执行。
- 重复决策返回 409；重复执行已执行审批返回幂等结果。
- 执行失败写入 `failed` 与审计（事务回滚时保留失败原因需生产化补偿）。
- 审批记录保存影响范围、金额、理由、payload、申请人、审批人、时间、回执、trace_id。

### 2.5 Agent

工作流节点与文档一致，但未强依赖 LangGraph：实现为可测试的同步状态机，便于在没有 LLM Key 的环境稳定运行。若需要 LangGraph，可将 `agents/graph.py` 的各节点函数直接映射为图节点。

- 工具注册表 `TOOLS` 声明名称、输入模型、角色、风险、超时、审计字段。
- Pydantic `extra="forbid"` 防止模型注入未知参数。
- 高风险工具 handler 内部只调用 `create_approval_request`，不会执行设备/资金动作。
- 回答固定包含数据来源、工具轨迹、状态、trace_id；配置 LLM 时只用于润色，禁止改变执行状态。
- 短期记忆：进程内字典，按租户/用户/会话隔离，30 分钟 TTL。
- 长期记忆：`agent_memories` 表只保存脱敏摘要与标签，不保存原始对话中的敏感字段。

## 3. 相对文档的取舍

| 文档设计 | 当前实现 | 原因与生产化建议 |
|---|---|---|
| MySQL 身份库 + PostgreSQL 业务库 | 本地 `docker-compose.yml` 同时提供 MySQL/PostgreSQL；当前实现以 PostgreSQL 为单一业务库，MySQL 连接已验证但暂未承载表 | 单库避免跨库事务与 ID 约束问题；生产若要拆分，将 `users/tenants/roles` 迁移到 MySQL，业务表保留 PostgreSQL，跨库只传 ID |
| Redis 短期缓存/锁/队列 | 进程内登录限流、会话记忆；数据库事务与唯一约束保证幂等 | 生产替换为 Redis：登录限流、分布式锁、Agent 会话 TTL、任务队列 |
| LangGraph + pgvector | 轻量状态机 + `agent_memories` 文本表 | 生产可接入 LangGraph 与 pgvector，仅替换 `agents/graph.py` 与记忆存储 |
| Agent/事件独立 Worker | 同步请求内处理 | 生产将设备事件、工单升级、Agent 长任务投递到 Celery/RQ，API 只入队并返回 202 |
| Nginx + 多进程 | Netlify CDN/Function + 容器 Uvicorn | Netlify 不支持 Python，采用代理架构；容器平台可水平扩展多个副本 |
| MySQL/PostgreSQL 高可用 | Render 单实例 PostgreSQL（Blueprint 默认） | 生产使用云数据库高可用、只读副本、PITR |

这些取舍不影响接口契约、权限边界、审批门禁与审计链路；替换基础设施时业务服务无需重写。

## 4. 安全实现对照

- **密码**：PBKDF2-HMAC-SHA256 210,000 次 + 16 字节随机盐，`hmac.compare_digest` 校验。
- **令牌**：JWT HS256，带 `iss/iat/exp/jti/typ`；刷新令牌 48 字节随机串，仅存 SHA-256 哈希，轮换时撤销旧令牌。
- **登录限流**：IP + 用户名维度，5 次/5 分钟（进程内；多副本需 Redis）。
- **注入防护**：全部 ORM 参数化查询；Agent 不执行 SQL/命令；工具参数 Pydantic 白名单。
- **敏感数据**：手机号序列化脱敏；日志不打印密码/令牌；Agent 记忆写入前正则脱敏。
- **响应头**：CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy；生产 HTTPS 加 HSTS。
- **审计**：关键写操作与权限动作落库，含 actor、role、resource、trace_id、IP、结果。

## 5. 测试覆盖

`pytest` 共 40 项，覆盖：

- 健康检查、登录失败、参数校验、令牌刷新/撤销、退出。
- 居民越权访问审计/审批/报表/用户接口。
- 运营社区范围、居民仅本社区、跨租户设备与事件隔离、跨用户订单读取。
- 订单幂等键重放与复用冲突、预约时段冲突与取消、订单开始/完成/异常状态机。
- 设备事件去重、故障自动建单、优先级、恢复事件、心跳更新、事件类型校验。
- 工单完整链路、未验收禁止关闭、测试订单设备不匹配、居民报修但不可处理、非法状态流转。
- 审批创建去重、通过、重复审批拒绝、执行、重复执行幂等、退款金额上限、种子退款审批执行。
- Agent 只读查询、故障诊断、审批查询、高风险转审批且不执行、居民高风险拒绝、居民总览走设备健康且不返回收入、居民仅本人订单、工具白名单。
- 看板、报表、社区筛选、CSV、审计查询。

前端使用 Playwright + 本机 Chrome 进行无头回归：登录、总览、设备详情、下单、审批决策/执行、工单创建/详情、Agent 高风险审批、移动端布局；无 pageerror / console error。
