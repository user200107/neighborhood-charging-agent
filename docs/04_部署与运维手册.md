# 部署与运维手册

## 1. 服务组件

生产部署至少包含 Nginx、FastAPI API、Agent Worker、事件处理 Worker、MySQL、PostgreSQL/pgvector、Redis 和集中式日志。各组件使用独立账号、网络和健康检查。

## 2. 启动检查

1. 检查环境变量和密钥来源。
2. 检查 MySQL、PostgreSQL、Redis 连通性。
3. 执行数据库迁移并确认版本。
4. 启动 API 和 Worker，检查 `/api/health`。
5. 使用受限账号验证登录、设备查询、订单查询和审批链路。

## 3. 监控指标

监控 API 延迟、错误率、登录失败、设备在线率、故障工单积压、订单失败率、Agent 工具失败率、审批等待时长、队列积压和数据库连接池。P1 故障需触发值班告警。

## 4. 备份与恢复

MySQL 和 PostgreSQL 执行每日全量、持续增量备份，备份加密并保留异地副本。每月进行恢复演练，验证用户、订单、设备事件、审批和审计数据完整性。

## 5. 故障处理

API 异常先检查健康接口、应用日志和数据库连接；事件积压检查 Redis 和 Worker；设备大面积离线时冻结自动批量动作并转人工审批；Agent 服务不可用时保留人工运营接口和工单流程。

## 6. 回滚

应用回滚使用上一版本镜像；数据库变更必须提供向后兼容迁移和回滚脚本。涉及订单、退款和审批的数据变更不得直接删除，采用状态修正和审计补偿。
